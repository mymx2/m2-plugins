# 规约语气（Standards Tone）

> **怎么用这份文件**：写或改规范 / 规约 / 标准 / 约定类文档（任何项目、任何领域）时加载。它管语气，不管格式：等级标注、条目排布、正例反例怎么来，随目标文档已有习惯，这份文件不规定。规则与语言无关，示例只说明形状。它是语气目录，不是逐句清单；先识味再判断，自然的句子别动。

## 一句话

规约的句子是发布语：对不在场的所有未来读者下判断。条款下命令，理由讲机制，教训讲事故；不辩护、不记录决策、不评价文档自身。

## 条款下命令

- 义务情态词（如 必须 / 禁止 / 不得）作主句谓语，不埋进从句或名词化结构；一条只下一个判断，短、无条件、可判定。
- 主语给被规范的对象；章节自身不作主语：一旦「本节」当主语，「本节与其他节怎么协调」这类话就会长出来，它是写给评审者的，不是写给读者的。
- 义务强度随目标文档既有等级，不升级、不降级。
- 义务不外包给流程：「条件 + 程序 + 记录」式的例外条款是正当内容；条款本体没有可判定行为、只剩「须经评审 / 须评估后决定」的，才是外包。
- 同类条款保持同一构成（要不要说明、要不要例子，全篇一致）；一致性让读者能扫读，是可预测性，不是格式规定。

## 理由讲机制，不讲立场

理由回答"运行时会怎样"：哪一步失败、失败时会发生什么、谁受影响。用可验证的硬信息（边界值、真实故障、具体行为），不用评价（"更合理""更优雅"）。

- 改法：辩护句改事实句，把"为什么不能那样做"改写成"这样做的机制与后果"；回答质疑的句子直接删。
- 边界：项目特有的取舍可以进正文，但只以事实陈述出现。可留：可验证的现状与后果（"现有机制不记录 X"）；要删：方案比较、成本账、说服话术。理由独立成段还是括注随文档习惯；条款只下判断，机制与论证另起，短后果（"否则会抛出 X"）留在条款内。

## 教训可以热，命令必须冷

口语、比喻、调侃允许，但只在"让人记住后果"时，且必带信息：把抽象的失效讲成能想象的场景，或点破常见误解（"不要以为……"）。

- 例（可留）："这个值填错不会当场报错，只会在对账时以一笔对不上的差额暴露出来。"（场景具体、带后果、对任何读者成立）
- 作者的踩坑史与情绪本身不是信息（"我们当年栽过"）；要留就留它换来的后果（"这样写在 X 时会出错"）。
- 判据：这句话在解释"人会怎么栽"，还是在表达态度、回应质疑？只对"参加过讨论的某个人"有意义的句子不是热，是残留。

## 不解释文档自身

- 禁元叙述：解释两条规则如何协调、回应评审意见、交代"本条与其他条不冲突"。
- 跨引用只留短指针（指向目标条目即可），不写两节各自负责什么、为何互补。
- 禁自我减损：不给本规约的要求打折扣（"仅为形式合规"）。
- 判断只针对做法 / 产物，不针对规则自身的效力（"这个命名有歧义"可以；"这条要求勉强成立"不行）。

## 用词：自足优先

- 一概念一词，全篇收敛；同义变体是讨论痕迹，不是丰富。
- 判据是自足：读者离开这次讨论的上下文后，还能不能读懂这个词？行业通用词即便需要停顿也保留（换了反而丢准确）。
- 要换的是讨论里给东西起的临时叫法、团队内部简写；换词后必须仍指向同一对象 / 机制，不引入歧义。
- 口语不禁止；禁止的是依赖本地讨论上下文的词。

## Smells

- 辩护腔：条款里带着回答质疑的话（"……不然做不到 X"）
- 批注腔：给评审者看的协调说明进了正文（"本节与其他节不冲突"）
- 决策存档腔：权衡、成本、备选方案写进条款（应进决策记录，不进条款）
- 自我减损：给本规约的要求打折扣
- 表演性免责："仅供参考""视情况而定"这类保护性话术，删
- 义务外包：条款本体没有命令，只剩"须评估后决定"
- 同义复述：条款说一遍，理由把同一句再说一遍
- 变更史残留：条款带"本次新增""原 X 改为 Y""后续可能调整"这类字样；只写当下生效状态，历史进变更记录
- 不可测量副词：尽快、适当、必要时；换成阈值或触发条件

## Tests

1. 丢弃测试：删掉讨论背景，这句话还成立吗？→ 不成立就改写成事实句；改不出就删。
2. 质疑测试：它在对一个具体的人说话，还是在对所有读者陈述？→ 前者按同法处理。
3. 事故测试：口语 / 修辞带信息吗，服务于记住后果吗？→ 不带就删，或改成陈述。
4. 判定测试：只读条款，没参加过讨论的读者能判断符合 / 不符合吗（倾向性约定：能否给出一致判断）？→ 不能就补条件或阈值。

## 示意（虚构示例，只看处理方式）

原：`接口必须返回请求编号：调不通的时候客服拿着订单号根本对不上是哪次请求，日志里全是散的。`
病因：条款与理由挤在一句；理由收尾是抱怨口吻。

改：`接口必须返回请求编号。`
说明：请求编号把同一次调用的上下游日志串成一条链路；缺失时，客服用订单号无法确认某条日志属于哪次请求。
