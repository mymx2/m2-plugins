# 指标复盘与路线图更新

产品指标复盘（DAU/留存/漏斗/异常归因）和路线图、迭代状态更新时加载。

## 指标复盘模式

### 先建指标树

分析之前先拆解：顶端一个北极星指标，下面 L1 维度（用户增长、活跃、留存、转化效率、商业价值、满意度），再往下 L2 具体指标。拿着一个孤立指标就开分析，得出的结论找不到归属。

北极星因产品类型而异：社交 → 周活跃发帖用户；工具 → 周完成核心任务用户；电商 → 周交易用户；内容 → 周消费时长；SaaS/B端 → 周活跃团队。说明建了哪棵树。

### 核心读法

- **粘性**：DAU/MAU——>0.5 极高粘性，0.3-0.5 高，0.2-0.3 中，<0.2 低。
- **用户分层**：新增（渠道质量、激活率）、活跃（使用深度、功能渗透）、回流（回流原因、二次留存）。
- **留存曲线**：次日/7日/30日对照产品类型基准；曲线在零以上走平是健康，滑向零是漏桶，再多获客也填不满。
- **漏斗**：逐级转化；瓶颈是绝对掉量最大的一级，不是相对掉幅最大的一级。

### 异动归因（五步，按顺序）

指标异常波动时：

1. **量化**：确切变化量，对哪个基线（环比、同比、同期）。
2. **维度拆解**：渠道、平台、地区、用户层、版本——找到承载变化的细分。平均值会掩盖，细分会招供。
3. **时间对齐**：把发布、运营活动、故障、节假日叠到时间线上。
4. **排除候选**：埋点 bug、口径变更、季节规律、外部冲击——逐个拿证据排除，再点名原因。
5. **交叉验证**：活下来的解释必须同时能解释*没*动的部分。

### 分析陷阱（每个结论都要过）

- **辛普森悖论**：聚合趋势与分组趋势相反。引用聚合数之前先看分组。
- **幸存者偏差**：样本里只有活下来的（成功项目、留存用户、回复问卷的人）。问一句缺席的样本会说什么。
- **虚荣指标**：不论健康与否都上涨的数（累计注册、PV）。一个指标只有当坏结果能让它下降时才配当证据。
- **Goodhart 定律**：指标一旦成为目标就不再是好度量。对自报的优化目标打折。
- **基率忽视**：只给惊人比率不给底层基率。

### 产出

各 L1 维度健康判断（绿/黄/红，各附一句话依据）→ 异动归因链（什么动了 → 哪个细分 → 为什么 → 证据）→ 行动清单，带负责人和预期影响的指标。

## 路线图更新模式

### 状态聚合

当前迭代表：计划 / 已完成（含百分比）/ 进行中 / 未开始 / 阻塞，外加预计按时交付率。接受任何输入格式；用户口述的数字标注为口述。

### 延期归因（五类）

| 根因     | 典型表现                     | 改进方向                  |
| -------- | ---------------------------- | ------------------------- |
| 需求变更 | 开发中途改需求、加 scope     | 需求冻结机制，变更走审批  |
| 估算偏差 | 实际远超预估                 | 用历史数据校准，加 Buffer |
| 技术风险 | 方案不可行、性能瓶颈、技术债 | 前置技术调研 Spike        |
| 依赖阻塞 | 等其他团队/第三方/审批       | 依赖提前两周预警机制      |
| 人力变动 | 请假、离职、临时抽调         | 容量规划留 20% 缓冲       |

同一类原因连续出现 3 次以上，从任务备注升级为流程改进项。

### 里程碑评估

每个里程碑：目标日期、关键交付物、进度 %、状态（按时=进度≥时间进度且无阻塞依赖；有风险=略落后或有未解依赖；延迟=严重落后或关键依赖阻塞）、点名的风险项。

### 路线图视图与砍削

用 Now / Next / Later 呈现，每个位置附一句话理由。容量逼着砍时，按 prioritization-frameworks reference 的容量砍削顺序执行。

收尾给：状态小结、更新后的时间线、Top 3 风险及负责人、未来 2-3 个迭代的规划建议。
